## 2026-11-19 · T45 Weekly cadence and the new fields, wherever code reads values · implementer (opus-5.5)
- Did:
  - Checks. A dataset with `release_weekday` is weekly. `freshness.weekly_expected` picks the
    latest scheduled release whose `expected_by_et` has passed. Each holiday on the dataset's
    calendar in the seven days ending on that day delays the release by one business day.
    Until the delayed due time, a missing release is `skip` ("release delayed by holiday").
    After it, the usual grace ladder applies. A `1w` row counts for the release when its ET
    date falls in `[nominal data day - 6, release day]`, so last week's row never passes.
    Completeness counts weeks per feed in the same window.
  - Value readers. `VALUE_FIELDS` gains `level`, `net_position` and `open_interest`;
    `VALUE_INTERVALS` and `OFFICIAL_INTERVALS` gain `1w`; `DAILY_CLOSE_FIELDS` gains `level`.
    A `1w` row dated today is left out, like a `1d` row (P-009). Level and position fields are
    macro-family: their changes are in points, never a % of a value that may be zero or
    negative. A weekly value compares only with the previous week of the same
    source/dataset/field (`BASIS_WEEKLY`, "previous weekly value"). `field_label` returns "net
    speculative position" and "open interest".
  - Report. `1w` values show a date only. Their change reads "week-on-week, since previous
    weekly value (date)". Contracts print as whole numbers. A `weekly` known limit names the
    weekly series, which get no anomaly check.
  - Dashboard. `build_bars` reads `1d` and `1w` rows and the new fields. It returns an
    `interval` column and never mixes weekly bars into a daily series. The tearsheet labels
    `1w` "weekly" and shows a weekly change as "WoW". Level series move in points.
    Daily-move statistics on a weekly or level series show a note instead of a number.
    `_FIELD_TEXT` gains the three fields.

  - Before this card, the tearsheet's log returns would have raised on a negative NFCI or net

  - One existing tearsheet test builds bars without `interval`, so `_is_weekly` treats a frame

- Decisions:
  1. Weekly is keyed on `release_weekday` (T44), not on the instruments' feeds.
  2. The weekly logic lives in `freshness.py` (owned), not in `checks/base.expected_for`
     (not owned). Completeness imports it.
  3. The holiday rule is generic (one business day per holiday in the release week) and does
     not model CFTC's or FRED's exact release calendars. A real release that comes later than
     the rule allows fails after grace; the source cards can tune `expected_by_et` and
     `grace_minutes`.
  4. The change unit for contracts stays `pts`, because `report/excel.py` (not owned) has no
     number format for any other unit. This is noted as a follow-up.
  5. Edits stay in the owned files. Some go beyond the symbols the card names, where the
     acceptance criteria need them: `family_of`, `overnight_changes`, `_official_change` and
     `BASIS_WEEKLY` in `query.py`; `value_text`, `_tail` and `_known_limits` in `model.py`;
     `BAR_COLUMNS` in `data.py`; `_mode`, `_move`, `_moves` and `risk_html` in
     `tearsheet.py`. All are listed in the PR.
