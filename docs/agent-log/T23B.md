- Decisions:
  - Only rows identical in every column except `run_id` collapse; a restated value, new `fetch_id` or new `parser_version` is a distinct version and stays. `run_id` is never checked against the file name, so rebuild files (`run={run_id}-{YYYY-MM}.parquet`, rows keep the real `run_id`) are accepted.
  - Order of operations: write the compacted file, read it back and compare the row count, then delete only the keys that were merged. A mismatch restores the earlier compacted file (or removes the new one) and raises with every input still in place.
  - Crash between the write and the deletes: no data is lost or unreadable, because the compacted file is complete and verified before the first delete. Until the next run the leftover inputs hold exact copies of rows in the compacted file, so a raw `obs_all` read sees duplicates while `obs_latest` (one row per key) does not; the next compaction merges the compacted file with the leftovers and finishes the deletes. This cannot be made atomic on R2 (no multi-key transaction), so the test pins that behaviour (`test_a_crash_between_the_write_and_the_deletes_loses_and_corrupts_nothing`).
  - Scope is `observations` and `quarantine` for `ctx.target_date`; the other tables live outside `clean/` and are not compacted.
