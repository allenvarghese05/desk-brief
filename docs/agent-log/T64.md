- Did: `events` and `filings` tables (`schemas.TABLES`, natural keys, enums `event_kind`,
  `filing_form`, `filing_row`, `trade_side` from new StrEnums in `models.py`); both under
  `derived/` in `store/backend.TABLE_LAYER`, partitioned by the ET date of `ingested_at`
  (`store/datasets.PARTITION_RULES`); `KNOWN_SOURCES` gains `fiscaldata` and `edgar`;
  `SourceSettings.user_agent_env` (exclusive with `user_agent`); `SEC_MAX_RATE_PER_MIN = 600`

  `brief` (`regime_rules`, `quiet_label`, `mixed_label`, `related_pairs`, `note`), `events`
  (`horizon_days`, `fred_releases`) and `filings` (`companies`, `insider_days`, `holders`), all

  `tests/contract/test_t64_events_filings_contract.py`.
- Widened scope (planner, 2026-11-26): every `config.py` change T62, T65 and T66 need is in this
  PR so Phase 2 touches no contract file.
- Decisions: (1) `derived/`, not `clean/`: a clean rebuild re-parses observations only and its
  flip would drop these tables' newer partitions; they are re-fetched each run anyway.
  (2) Partition by fetch date, not event/filing date: one file per run per table, and the
  write-once-per-partition rule holds; readers use `schemas.current_rows` (round 1, below). (3) `filings` is one row per fact (seq 0 = the filing), so Form 4 trades and 13F
  holders need no nested columns. (4) `plan_10b5_1` is a plain bool (the schema kinds have no
  nullable bool): true only when the Form 4 row marks it. (5) Regime rules and related pairs read
  rankable changes only (T61), so a non-like-for-like move can never decide the read.
  (6) `brief.note` carries list prices so T66 can enforce the monthly cap from token usage.
  (7) `fred_releases` carries a time per release because FRED's release calendar gives dates only.
- Review round 1 (planner, 2026-11-26): B1 the reader rule "newest `ingested_at` per key" left
  stale rows (a rescheduled release, a re-parse with fewer Form 4 facts). Now `REPLACE_SCOPE`
  plus one helper, `schemas.current_rows`: the newest run that wrote a scope (events per
  source+dataset, filings per instrument+accession) replaces it whole; with `source_log`, a newer
  all-successful events fetch with no rows empties it. Runs, not fetches, are the unit, so
  paginated or two-fetch writes stay whole. Rulings: "No clear read" (`unclear_label`) and
  `BriefSettings.read_label`; `previous_value`/`previous_unit` dropped (neither fiscaldata's
  upcoming auctions nor FRED's release dates give one); `NoteSettings.effort` (low) and
  `max_output_tokens` 8000 (min 2000); share classes may share a CIK; frame-level checks for
  `scheduled_at` on `event_date`, seq 0 = filing row, facts on their form, trade and holding
  fields, 13F `period`, 10b5-1 only on trades. A mutation run confirmed the old rule fails the
  three B1 tests.
