## 2026-11-17 · T07B Intraday tick-age freshness · implementer (sonnet-5.5)
- Did: added `IntradayFreshnessCheck` (check name `freshness_intraday`, type `freshness`) to
  `checks/freshness.py` and registered it. For each `Config.intraday` entry it takes the newest
  `interval = 'tick'` row from `obs_pit(now)` for that (source, dataset) and compares its age with
  `grace_minutes` through the existing `late_status` ladder (<= grace pass, <= 2x grace warn,
  beyond fail; inclusive at grace like `within_grace`). It evaluates only inside the XNYS session of
  the ET day of `now` and from open + grace; before that it returns `skip` with reason `pre-open`,
  `warm-up`, `after close` (marked early close when it is one, P-011), `holiday` or `weekend`. New
  tests in `tests/unit/checks/test_intraday_freshness.py` were run red first (collection error),
  then green; the checks and pipeline suites pass (254 tests).
- Went wrong: nothing.
- Decisions: (1) Runs in the `intraday` job only and returns no rows for other jobs: only that job
  polls ticks and it is already gated to the session, so skip rows from morning/eod/rebuild would
  be noise. (2) A feed with no tick at all after the warm-up is `fail`, not `warn`: a full grace of
  session with nothing means the feed is dead, and age is unbounded so it sits at the top of the
  ladder. (3) The age is `now - max(as_of)` across all instruments of the entry, so one live
  instrument keeps the entry fresh; per-instrument tick gaps stay with `feed_completeness`.
  (4) Ticks stamped after `now` are ignored. (5) Session hours exist only for XNYS
  (`calendars.session_bounds_utc`); an entry with another calendar gives `skip` with that reason
  instead of a guess. All three configured entries are XNYS. A generic per-calendar session helper
  in `calendars.py` would lift this (not mine to edit; proposal only).
