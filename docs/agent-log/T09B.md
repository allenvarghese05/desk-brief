- Did: `Row` gains defaulted fields `value`, `value_unit`, `change_value`, `change_value_unit` (typed numbers; the 2s10s row has bp values, so writers can drop text parsing) and `dq_flag` (`fail` > `warn` > `pass`, `skip` is no result, `none` otherwise; single-source checks by `instrument_id`, cross-checks for both instruments of the pair). New `query.instrument_flags`. `health_summary` and the flags read only the latest run for the target date, so rows of a superseded run stay in the store (P-008) but never count. `latest_snapshot` and `overnight_changes` take `exclude_tiers=`, applied to the last value and to the baseline. Notable moves now score like the T20 anomaly check (`daily_moves`, `MIN_MOVES`, `|move|` against the mean and sample std of the prior `|daily moves|`, one-sided `z >= z_warn`) instead of a second signed z-score. A future-dated delayed quote says so instead of "0 min old". `_spread_row` docstring explains the shared date. New tests for each bullet, including the tier-2 `1d` yield being ignored by 2s10s. Golden regenerated (new fields only). `SCHEMA_VERSION` stays 1 because every new field has a default and old JSON still decodes.
- Went wrong: nothing blocking. The sandbox denies `.env.example`, so the branch was made with `git branch` plus `git symbolic-ref` and pytest needed `-c pyproject.toml --rootdir=tests --confcutdir=tests`. A first `ruff format` pass reformatted one line of `query.py`.
- Decisions:
  - "Latest run" is the run_id of the newest row (by `evaluated_at` / `at_time`) of that table for the date, taken per table. It does not join to `runs`, because `runs` can lack a row for a run that wrote results and the synthetic fixtures do not link them. The mirrored `consistency` rows are ignored when finding the run.
  - Notable moves use the anomaly check's one-sided score: a reversal of normal size is no longer flagged, and a large move in either direction still is (it is the magnitude that counts). Unit is taken from the history series (bp for yields, return otherwise) so the overnight move and the history use the same function.
  - The derived 2s10s row is not an instrument, so its `dq_flag` is the worst flag of its two legs (`UST_10Y`, `UST_2Y`). T32B may prefer `none`; it is one line in `BriefModel.from_store`.
  - Typed `value`/`change_value` are set on every available row, not only the derived one, so T32B needs no special case. Non-derived rows still carry `change` (the `ChangeRow`) as before.
  - The future-dated guard cannot be reached through the store (`obs_pit(at)` and `as_of <= at` keep out later rows), so the test calls `_qualifiers` directly. It guards the formatter if the cut ever changes.
  - `exclude_tiers`: an instrument whose every row is excluded is absent from the snapshot (and shows "data unavailable" in the model), as if it had no data.
