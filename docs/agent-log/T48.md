## 2026-11-19 · T48 Yahoo daily history for ETFs and single stocks · implementer (opus-5.5)
- Did:
  - `config.yaml`: one `{source: yahoo, dataset: history, tier: 2}` feed for each of the 12 ETFs
    and stocks (SPY, QQQ, IWM, AAPL, MSFT, NVDA, USO, BNO, GLD, SHY, IEF, TLT). The Stooq feeds
    and `enabled: false` are untouched; `daily_fallback` still has no feeds.
  - `sources/yahoo.py`: `plan_range(start, end, ctx)` for `history` only. It returns one request
    with every history symbol and an exclusive `end`. `fetch` already makes one yfinance call per
    symbol, so 2 years is one call per symbol. Docstring records the unadjusted close.
  - `crosschecks/close_official.py`: the reference is the Yahoo `history` close instead of
    Stooq. Members are `iex_vs_sip.symbols` with SIP bars and a Yahoo history feed.
  - `crosschecks/proxy_exact.py`: `details.provider` is `"same provider"` or `"different
    providers"` when both legs are present. It is a label only and never changes the status.
  - Tests:
    - `tests/unit/sources/test_yahoo_t48.py`: config coverage, P-003, `plan_range`, and a
      2-year range through fetch and parse.
    - `tests/unit/crosschecks/test_xc_t48_yahoo_history.py`: a three-month store built through
      the real parser. All 12 dead keys compare, the same store without ETF history skips, and
      `build_bars` draws SPY and MSFT in hosted mode.
    - Updated `test_xc_close_official.py` (Stooq to Yahoo) and `test_xc_proxy_exact.py` (provider
      label, Yahoo proxy legs).
  - `docs/sources/yahoo.md`: the P-019 section, adjusted vs unadjusted close, freshness and
    completeness, `plan_range`, and the live probe.
- Went wrong:
  - The worktree had no `.venv`. `uv sync --frozen --all-extras` failed on the sandboxed uv
    cache; it worked with `UV_CACHE_DIR=$TMPDIR/uvcache`.
  - A `curl` call to Yahoo's chart API with a browser User-Agent was refused by the permission
    gate. That was right: spoofing a UA is close to working around a bot check. The HTTP status
    came from yfinance's own debug log (`response code=200`).
  - `FetchRequest` and `RunContext` are dataclasses, so `dataclasses.replace` is needed, not
    `model_copy`.
- Decisions:
  1. **Unadjusted close** (`auto_adjust=False`, `Close`), as before. The card doesn't name one,
     but `close_vs_official` needs the traded price. Returns across ex-dividend dates include the
     dividend drop; this is documented as a known limit.
  2. **No `yahoo/history` freshness entry added.** None existed. Per-instrument completeness for
     `yahoo/history` already exists in `feed_completeness.py` and picks up the new feeds. A
     `config.datasets` entry would make `completeness.py` judge every history feed a second
     time on one calendar, failing the foreign indices. That is check behaviour outside T48's
     Owns, so it goes to the planner as a follow-up.
  3. **Stooq feeds left in `config.yaml`.** The brief said not to touch Stooq. The tier-ordered
     readers try Stooq (tier 3) first, find nothing and fall through to Yahoo.
  4. **No Yahoo quote feeds for the new Cboe indices.** T48 owns the Yahoo `history` feeds, not
     the quote feeds. Listed as a follow-up.
